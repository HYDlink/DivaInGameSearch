# 验收范围

本地 Windows 补丁复核：MSVC 编译与五组 CTest 通过；63 项核心断言、53 项定制物品检查、输入与 DX11 宿主、视图行为、DLL 回调及原生预览通过。仅消息快速退出的后台任务生命周期缺陷已修正，并补充回归。以下云环境记录保留为历史，最新边界见 [补丁检查报告](CLOUD_PATCH_REVIEW.md)；本次补丁尚未做真实游戏验收。

1.0.0 的测试分为自动验证、原生界面预览与实际游戏操作，三者不能相互替代。

| 范围 | 结果与边界 |
| --- | --- |
| 检索与数据 | 核心断言覆盖 Unicode、别名、读音、组合过滤、排序、来源合并等 |
| 定位状态机 | 覆盖稳定菜单、错误状态、超时、恢复、缓存与真实高亮分离，以及直接路径不请求菜单切换 |
| 输入与 DLL 宿主 | 原生输入协议测试与 DLL 回调检查通过；不能等同全部 IME 实机通过 |
| UI | 共用 DX11/WARP 预览检查分组、彩色按钮、选中行与长列表 |
| 实际游戏 | 用户确认直接定位可用；连续实际读回包含同曲极限→EX 极限、简单→困难，以及换曲同时切难度 |
| 菜单备用协议 | 受控工具验证两次歌曲/困难定位，不代表 UI 中提供两种模式 |

实际定位实测主要为街机风格。跨风格、Eden、不同构建、IME、DPI、所有 Mod 组合及长期稳定性尚需补充。快速定位后的封面或作者同步存在已观察到的局限。

复现自动检查：

```powershell
./scripts/build.ps1
./scripts/verify.ps1 -GameDirectory '游戏安装目录'
./scripts/check-profile.ps1 -GameDirectory '游戏安装目录'
```

游戏内回归应核对菜单高亮、实际难度、风格、可见画面与诊断。不要仅凭函数返回或请求缓存宣称成功；不要为测试自动开始演奏或改写存档。

当前开发树新增 `ViewCheck`，覆盖同帧累计上下移动、左右跳过缺失难度与边界、换曲保留难度、防抖、过期结果丢弃、IME 暂停、新曲库索引失效，以及 Enter 等待最新结果且只提交一次。`InputCheck` 增加缺失释放消息、物理按住屏障、失焦清理、窗口链转发与导航焦点检查。构建脚本通过 CTest 自动执行这两项；原生输入仍需 Windows DX11 与实际游戏验证。

2026-10-29 云环境验证：修改的核心、界面、宿主和诊断源码通过 MinGW Windows x64 编译检查；`SearchTests.exe` 在 Wine 下通过 63 项断言，`ViewCheck.exe` 在 Wine 下通过视图行为、真实 ImGui Tab / Shift+Tab 焦点和 Esc 取消回归。提取真实 Host 输入方法并替换系统 API 的可移植桩通过 ASan/UBSan。`InputCheck.exe` 已交叉编译，但 Wine 无法初始化 DX11 WARP，未执行原生输入协议验收；仍需 Windows MSVC 构建、原生 DX11、实际 IME 和游戏回归。兼容环境或 API 桩通过不等于实机通过。

服装／饰品整合后的最终版本统一重新编译：`CustomizationCheck.exe` 在 Wine 下通过 53 项；`ViewCheck.exe` 通过三领域条件隔离、真实 Tab 进入格子、有序方向动作、Enter 详情、Esc 返回及原生能力禁用；`InputCheck.exe --messages-only` 在 Wine 使用真实 Win32 消息后端通过 IME 消息、长按保护、缺失／迟到释放、前窗口链、模式切换及歌曲／格子路由。消息模式没有创建 DX11 设备，不等于完整 `InputCheck` 或物理键盘／输入法实机通过。独立 Preview 的源码已交叉编译检查，云环境未做可视截图或实际游戏定位。

收到截图触发反馈后，宿主补充应用／窗口失活清理。重新交叉编译并在 Wine 通过消息回归：未收到任何释放或 `WM_KILLFOCUS`，仅收到 `WM_ACTIVATEAPP(false)` 或 `WM_ACTIVATE(WA_INACTIVE)` 时也清空隔离、保护时间与动作，继续转发前窗口过程；恢复激活不误关闭搜索。用户旧版日志没有焦点／隔离记录，不能据此确认其截图工具具体发送了这些消息，真实截图工具复现仍待本机验证。
