# 界面多语言

支持简体中文（源语言）、英文和日文。玩家通过 `settings.ini` 的 `language` 选择，`auto` 时跟随 Windows 界面语言：中文用简中，日文用日文，其余用英文。修改后重启游戏生效。

## 文件

| 位置 | 作用 |
| --- | --- |
| `locales/zh-CN.toml` | 源语言，新增文案先写这里 |
| `locales/en.toml` | 英文，必须完整；其他语言缺键时回退到它 |
| `locales/ja.toml` | 日文 |
| `tools/i18n_gen.cpp` | 构建时生成 `Tx` 枚举和内嵌文本 |
| `src/i18n.h` | 运行时接口 `Tr`、`Trf` |
| `scripts/check-i18n.ps1` | 检查玩家可见代码没有硬编码中文，随 ctest 运行 |

所有语言都内嵌进 DLL，发布包不需要额外文件。

## 新增文案

1. 在 `zh-CN.toml` 和 `en.toml` 加同一个键，日文也一起补上。`[song]` 下的 `results` 在代码里是 `Tx::song_results`。
2. 代码里用 `Tr(Tx::song_results)`；带变量用 `Trf(Tx::song_results,{{"count",std::to_string(n)}})`。

构建时生成器会校验：键名合法、en 完整、其他语言没有多余的键、占位符与源语言一致。任何一项不符都会让构建失败。

## 约定

- 写整句模板，不要用 `+` 拼句子，否则语序无法翻译。
- 译文不能当 printf 格式串。要用 `ImGui::TextUnformatted(...)` 或 `ImGui::Text("%s",...)`。
- 不要用显示文字做逻辑判断，用枚举或状态字段。
- 尽量避免依赖单复数，比如英文写 `Results: {count}`，不写 `{count} results`。
- 控件 ID 与显示文字分开，比如 `Tr(...)+"###card-preview"`。
- 诊断日志、来源诊断面板内容和性能录制只面向开发者，保持中文。

## 内容语言

物品名称跟随 Mod 界面语言读取游戏语言表（简中 `cn`、日文 `jp`、其余 `en`），不读取游戏当前语言：玩家可能让游戏和 Mod 使用不同语言。英文界面的主标题用英文歌名，第二行显示原名。

字体：简中优先微软雅黑；其他语言优先 Yu Gothic、Meiryo，避免日文汉字显示成中文字形，缺字由雅黑补齐。

## 术语

术语优先沿用游戏 `rom/lang2/<语言>/str_array.bin` 的官方译法。

| 简中 | 英文 | 日文 |
| --- | --- | --- |
| 模型 | Module | モジュール |
| 发型 | Hairstyle | 髪型 |
| 自定义道具 | Accessories（暂定） | カスタマイズアイテム |
| 搭配模型 | Match Module | モジュールにあわせる |
| 歌者 | Singer | ボーカル |
| 衍生角色 | Extra Characters | 派生キャラ |

## 检查翻译

`./scripts/preview-languages.ps1 -GameDirectory '游戏目录'` 为每种语言和页面各截一张图，保存到 `artifacts/languages`，需要在桌面会话运行。`SearchPreview.exe --language en` 可以单独预览一种语言。`--language qps` 是伪翻译：文本加长约 40% 并带重音字符，用来发现布局溢出和遗漏的硬编码。

不用编译也能试改译文：把语言文件放到 Mod 目录的 `lang/<语言代码>.toml`，其中的键会覆盖内嵌文本。不合规的条目会被跳过，并写入 `search-diagnostics.log`。
