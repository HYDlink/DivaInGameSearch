# 搜索后游戏按键失效：排错与日志

搜索面板打开时，本 Mod 暂时隔离游戏的原生输入，避免输入曲名、Enter 定位时同时触发游戏操作。面板关闭后保留 120 毫秒释放保护；仍按住的按键或鼠标释放前，继续隔离，避免长按 Enter 开始演奏。

旧实现只依赖窗口的 key-up / mouse-up 消息清除待释放记录。如果输入法改变了释放消息的键值，或窗口消息链没有把释放送到本 Mod，任意一项记录都可能使 `captures` 永久为真，表现为搜索已关闭但整个游戏无法响应按键。这是从代码确认的残留路径，尚不能证明每一次用户反馈都由它造成。

修复后，关闭面板并经过释放保护期，会逐帧核对物理按键状态，清除已松开但缺少释放消息的记录；仍按住的 Enter 和鼠标不会按固定超时放行。稍后才到达的释放消息仍会被消费，新一轮正常按下和释放可完整转发。失焦、窗口重绑和安装失败也会清理本 Mod 的隔离状态。保留原生输入 Detour 及前一窗口过程的调用链。

截图覆盖层可能只发送应用／窗口失活消息。除 `WM_KILLFOCUS` 外，开发版也在 `WM_ACTIVATEAPP(false)` 和 `WM_ACTIVATE(WA_INACTIVE)` 清理面板、待释放项与保护时间，并将通知继续交给前窗口过程。收到恢复激活通知不会自动打开或关闭面板。

## 2026-10-29 截图触发反馈

反馈指出没有使用输入法，在搜索打开时触发全局截图，此后游戏按键提示大部分变空、键盘／鼠标／触屏失效，但 Ctrl+F 仍可操作搜索，关闭搜索后仍无游戏输入。这与插件窗口快捷键仍运行、游戏原生输入却继续被隔离的机制相符；不需要 IME 才可能触发缺失释放。

该次旧版日志在 08:36:49.244 打开搜索，08:37 无记录，08:38:05.581 仍接受定位并在 08:38:05.808 确认实际高亮；08:39:32.450 出现新一次初始化。能确认定位回调仍运行及日志保留了前后初始化，不能证明截图时确实收到哪条失焦通知，或具体残留了哪个键。旧版正常收到 `WM_KILLFOCUS` 也会清空待释放项，因此不能把「截图后疑似失焦」直接当作已确认根因；需要区分释放消息被截走、只收到失活通知、未收到失焦通知等情况。

回归补充只收到两种失活通知、没有 key-up／mouse-up／WM_KILLFOCUS 的场景，核对隔离完全解除、恢复激活不误关闭搜索、前窗口过程仍收到通知。真实 QQ／系统截图工具的消息序列仍需本机复现与开发版输入摘要日志确认。

## 先保留现场

遇到问题先记下时间、打开搜索的方式、是否使用中文或日文输入法、如何关闭、是否按住 Enter 或鼠标，以及键盘和手柄是否同时失效。先松开所有按键和鼠标，等待片刻；必要时 Alt+Tab 切出再切回，观察失焦清理后是否恢复。面板仍可操作、按 Ctrl+F 可重新打开、手柄能否操作，都是有用的区分信息。

不要为了排错自动开始演奏、强制结束进程、改写存档或调整其他 Mod 的顺序。需要重启时正常退出即可。

## 日志在哪里，重启是否覆盖

本 Mod 日志位于游戏目录下的 `mods/DivaInGameSearch/search-diagnostics.log`。若安装时改过文件夹名，以实际承载 DLL 的目录为准。

日志使用 `std::ios::app` **追加写入**，每条记录独立打开并关闭文件；正常重启游戏不会清空旧内容。输入捕获标记保存在进程内存中，重启游戏会重新建立这些标记，与日志文件是否保留无关；旧版仍可能在后续搜索时再次触发残留。当前代码没有自动轮换、截断或清理日志。删除、手工清空、替换整个 Mod 目录或由外部工具覆盖文件，才可能丢失历史。升级部署脚本会备份已有日志，但仍建议在更新前另存一份。

Windows PowerShell 可在游戏安装目录执行以下命令，保存一份带时间的现场副本：

```powershell
$logPath = '.\mods\DivaInGameSearch\search-diagnostics.log'
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
Copy-Item -LiteralPath $logPath -Destination ".\search-diagnostics-$stamp.log"
Get-Content -LiteralPath $logPath -Encoding UTF8 -Tail 150
```

若本 Mod 文件夹名称不同，先调整 `$logPath`。运行中复制是只读收集；最后一条正在写入的记录可能还没完整，正常退出后可再复制。日志没有出现或时间不更新时，先确认本 Mod 已加载、实际 DLL 目录和写入权限；写入失败时修复版也会向 Windows 调试输出发送提示。

## 应提供哪些片段

提供故障前后时间段，包含最近一次“已初始化原生搜索”、版本与构建检查、“打开搜索”、“搜索快捷键”、“定位请求 / 定位阶段 / 结果”，以及修复版新增的“输入隔离切换”、“搜索面板关闭”、“输入释放恢复”和“输入状态清理”。初始化行包含本次进程 PID，可区分同一日志中的多次启动。

输入摘要中的“面板”表示搜索是否打开，“隔离”表示是否暂时拦截游戏原生输入，“待释放键 / 鼠标”是计数，“释放保护”表示短时间保护是否生效。关闭后“隔离=1”且仍有待释放项，需要结合是否确实按住按键判断；“输入释放恢复”说明已清掉没有收到释放消息的记录。诊断仅在状态变化时记录，不逐帧或逐字记录查询输入。

同时说明游戏版本、Mod 版本、其他输入或 UI Mod、输入法、窗口或全屏模式、复现步骤、问题时间和切出切回是否恢复。已有旧版日志没有这些输入摘要，只能帮助核对定位阶段，无法直接证明捕获是否残留。分享前检查并移除个人路径或其他不愿公开的信息；无需上传游戏文件、存档或完整私人日志。

## 验证边界

`InputCheck.exe` 增加了可控的物理状态探针，覆盖缺失或键值改变的释放消息、缺失鼠标释放、长按保持屏障、失焦后的保护清理、前窗口过程转发和导航消息累加。Windows 上先构建，再运行：

```powershell
./scripts/build.ps1
./build/release/InputCheck.exe .
```

这些是宿主协议回归，不能代替游戏内验证。仍需在实际游戏中覆盖 Enter / Esc / Ctrl+F / 点击关闭、中文及日文 IME、长按 Enter / 鼠标、Alt+Tab、手柄和其他输入 Mod 共存。Linux 环境无法运行 Windows DX11 宿主或实际游戏，不能据此宣布实机修复已通过。
