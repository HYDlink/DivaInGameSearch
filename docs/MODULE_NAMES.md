# 自定义搜索面板的服装名称

只修改搜索面板里的服装显示名和检索名，游戏原生服装菜单保持原样。无需编辑器界面，也不需要修改其他 Mod 的文件。

## 最快的用法

1. 在游戏里打开一次“模型”搜索，等服装目录加载完成。
2. 在本 Mod 文件夹、`settings.ini` 同级找到 `module_names.toml`，用支持 UTF-8 的文本编辑器打开。
3. 搜索当前服装名称，或对照卡片上的 ID，修改该行等号右侧的引号内容。
4. 保存后，在模型搜索的“选项”中点击“刷新目录”；也可以重启游戏。

例如，把编号 0 的服装在搜索面板中显示为“我的初音”：

```toml
[module]
0 = "我的初音" # 当前名称：初音未来；实体原名：初音ミク
3 = "" # 留空沿用现有名称
```

`[module]` 只写一次。上面是格式示例，实际目录中的名称、角色与来源以本机自动生成的参照为准。修改名称不会改变服装 ID，仍能用原名、之前的 Mod 显示名和 ID 搜索。

## 怎么对照服装

首次生成的 `module_names.toml` 已列出当前全部有效服装，每行右侧的注释依次是：

**当前名称 → 实体原名 → 角色 → 定义来源 → COS**。

行首数字就是搜索卡片显示的 ID。相似服装可在面板里按 ID 搜索并查看图片，确认后再填写。这里只列模型，不把发型、道具的同编号混进来。

程序还会生成 `module_names_reference.toml`，格式与个人表一致，始终列出当前有效服装的默认名称与来源，不包含个人改名。增删 Mod 后刷新目录，这份参照会更新；个人表始终保留。需要给新服装改名时，从参照表复制对应行到个人表已有的 `[module]` 分组下，再填写名称。已有的编号行直接修改，不要重复添加。

## 优先级和保留规则

- 个人表中的非空名称优先于 Mod 名称补丁和官方译名；它对搜索面板的所有界面语言生效。
- 空字符串或纯空格表示沿用原名称。清空、删除该行或删除个人表后刷新，即可恢复默认显示。
- 个人表只修改显示与检索，不创建物品，也不修改角色、COS、来源定义、推荐关系、拥有状态和换装目标。
- 不存在的 ID 会被忽略并写入诊断；同一 ID 在不同 Mod 组合下可能代表不同服装，分享个人表前应对照双方来源。
- 用户表只在不存在时生成，程序不重写用户注释和排版。自动参照表会刷新，请把改名写在个人表里。
- 文件必须保存为 UTF-8。TOML 语法或编码错误时，本次使用原有名称，并在 `search-diagnostics.log` 记录原因；用户文件不会被自动修复或清空。
- 名称最多 1024 个 UTF-8 字节，不接受换行、Tab 等控制字符。双引号写为 `\"`，反斜杠写为 `\\`；名称表上限 8 MiB。

修改个人表后使用现有“刷新目录”即可，无需专门的改名界面。个人名称不参与游戏资源指纹，因此单纯改名不会触发“游戏资源需要重启”的提示；真正增删 Mod 或修改实体表仍按原有规则处理。

## 开发验证

个人名称处理位于 `src/user_module_names.cpp`，在来源与语言合并完成后、检索索引构建前执行。文件读写在目录后台加载任务中完成，不在每帧绘制中扫描文件。

游戏目录仅作为数据来源；审计工具的插件目录参数会生成两份名称文件。生成本机参照的开发命令为：

```powershell
./build/release/CustomizationAudit.exe '用于输出名称表的插件目录' '游戏安装目录' '审计输出.tsv' cn
```

当前实现保持既有版本号；新功能的构建、发布与部署状态见验收记录。
