# 官方与 Mod 服装预览方案

日期：2026-10-29。目标是一个DLL或一个Mod ZIP安装后可用；玩家不需解包、导图、填写清单或安装Python。本文记录资源结构核查和实施方案，不表示图片解码、官方资源运行时读取已完成。

## 正式运行的自动资源链

1. 从启用Mod的实体表建立稳定Module ID目录；同时取得官方基础／DLC实体。实体、名称、图片来源独立，支持只有图片替换的高优先级Mod覆盖官方图片。
2. 通过当前生效sprite数据库定位 `MD_IMG`／`MD_IMG_FT`、集合与资源路径。按DML及游戏资源优先级解析，不能用“ID等于纹理ID”或归档文件名猜最终映射。
3. Mod散文件由插件直接读FARC。官方CPK资源优先调查并验证游戏已有只读资源读取接口，借它读取已挂载CPK及DLC，避免要求玩家导出。未验证前不能声称该接口已可用。
4. 若原生只读资源接口不可用，评估已有、许可证兼容且可内嵌的CPK读取组件；遵守复用约定，不重新编写CPK提取器。若需要依赖文件，随一个Mod ZIP提供，安装仍只需解压。开发资料里的F盘路径、FarcPack和.NET工具不能成为玩家运行依赖。
5. 后台执行FARC读取、纹理格式识别和解码；按精灵纹理索引及UV取得正确图像，处理透明度、方向、边界和风格缺失。缓存由插件自动生成，键含资源来源／指纹、精灵、风格及解码器版本，不需玩家操作。
6. 用现有DX11设备在受控线程上传纹理；只加载可见卡片和少量邻近项，限制尺寸、内存和并发，LRU回收。窗口／设备重建后重新上传。不能将未验证的游戏纹理裸指针传入ImGui DX11。

官方资源自动读取是交付门槛，不能把“已有F盘开发缓存”作为完成条件。先拿官方0／316／394、Mod1400／6400／997验证完整像素链和覆盖，再扩展全目录。发行包不附带整套游戏图片，读取玩家已安装资源。

## 大图卡片与悬浮详情

- 图片占主要面积。当前样式稿将预览区提高到280像素，文字固定两行：第一行名称（超出省略），第二行角色分类与ID；Mod来源和完整名称进入悬浮详情，不额外堆叠四五行文字。
- 默认使用对齐的行列Grid并自动换行，不采用会改变视觉顺序的dense填洞或自由瀑布流。普通图占一列；经真实图片宽高比判定的宽图可占两列，窄窗口回退一列。无宽图时维持常规格子。
- 图片按比例contain完整显示，不拉伸、不裁掉头饰、长发或裙摆。绘制比例为 `min(可用宽/图宽,可用高/图高)`。透明大边距可在验证alpha边界后无损收紧，但不能裁掉任何非透明像素；原始尺寸仍保留。
- 超高／超宽导致主体过小时，在悬浮或键盘聚焦详情里放大查看，限制在屏幕范围内，必要时提供固定详情操作。适配使用精灵区域而非原始图集宽高；最终宽图阈值与列跨度以真实资源全量尺寸统计确定。
- 悬浮详情提供完整名称、其他语言名、角色、ID、实体／名称／图片来源和覆盖状态；键盘聚焦同样可查看。鼠标离开、滚动、筛选变化时关闭旧浮层，避免串项。生产实现增加合理悬浮延迟。
- 原生键盘导航根据实际卡片矩形寻找同方向邻近项，不能在双列宽卡片布局中简单使用selected±columns。视觉与数据顺序保持稳定，选择、定位与滚动互相独立。

样式稿已实现两行文字、较大图片占位、悬浮／聚焦详情和独立的1:3／3:1几何测试区；测试区仅用于比例评估，不伪造真实服装图。真实图片、双列自动分类和最终原生键盘导航仍待实现。此前右侧常驻大详情改为下方紧凑所选操作区，为Grid释放宽度。

## 验收

在没有F盘开发资产、没有手工导入清单、没有外部工具的干净环境安装单个Mod ZIP，能够自动显示官方及已启用Mod服装图片；核对名称、Module ID、sprite与来源一致。覆盖透明超宽图、超高图、图片替换Mod、缺风格、坏归档、官方DLC、不同语言、窗口缩放、设备重建和大库滚动。独立布局预览不计为游戏内图片或定位通过。
