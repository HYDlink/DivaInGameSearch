# 服装搜索两阶段实施计划

日期：2026-10-29。当前交付为实施计划、真实 Mod 数据核查与可交互布局稿；尚未修改生产 DLL、部署或新增实际游戏定位验收。

## 明确的目标

复用 Ctrl+F、歌曲／服装／饰品模式。服装支持名称、其他语言名称、别名、ID 与关联 Mod 搜索；可按角色、来源和排序组合过滤。结果采用自动换行卡片（wrap layout）、纵向滚动和键盘选择，展示名称、角色、Mod 来源、ID 与缩略图／明确缺图占位。选择后定位原生服装列表中的真实条目，不自动装备或购买。

复用现有 customization* 与歌曲的 DML 来源发现规则。已有代码完成本地导入、基础搜索与卡片浏览；本轮主要缺口是自动读取真实 Mod 归档、原生定位接线和最终 UI。饰品浏览保留，发型与饰品原生定位另行研究。

## 真实 Mod 样本结论

只读检查用户指定的两个安装目录，按普通 FArC 目录读取指定内部条目并用 gzip 解压；未修改 Mod 文件。两个 config 都 enabled=true、include=["."]，游戏顶层 DML priority 都包含对应目录。仅此不证明整个游戏当前运行时集合无覆盖。

| Mod 目录身份 | Mod 显示名 | 实体表记录 | 元数据角色 | 示例 |
| --- | --- | --- | --- | --- |
| Project Megpoid Module Pack | Project Megpoid Module Pack | 20 件 | 全部 SAKINE | ID1400 Megpoid GUMI、ID1439 V3 Adult、ID1495 AI Megpoid SV |
| X Song Pack | Project Diva X Song Pack | 1 件 | MIKU | ID997，COS_482，初音未来 XHD 风格 |

两者均为 `rom/mod_gm_module_tbl.farc` → `gm_module_id.bin`；其中 `.bin` 是 UTF-8 键值文本。实体按 `module.<序号>` 归组，以字段 id 为稳定身份，不能拿序号或 COS 数字当 ID。

Megpoid 的 20 个 ID：1400、1439、1440、1441、1457、1458、1459、1483、1484、1485、1486、1487、1488、1489、1490、1491、1492、1493、1494、1495。

Megpoid 名称文件含实体表外的 module 名称；孤立名称只记诊断，不能增加服装数量。名称补丁还有多语言／英文别名，可关联已有 ID。GUMI 在这里占用 SAKINE 元数据分类：默认按真实角色筛选；GUMI 可通过名称、Mod 或显式可配置展示标签检索，不能新增虚构原生 GUMI 枚举，也不能未经实测将 SAKINE 枚举序号写入 UI 分类。

X 使用旧式平面名称：1272 / cn.1272，对应实体997，样本差值为275。中文显示“初音未来 XHD风格”，原表名称“初音ミク XHDスタイル”保留为检索名。后续兼容仅映射已有实体、明确支持的构建和命名空间；不能把所有数字都减275。发型名称2236属于独立领域，不能生成服装卡片。

Megpoid 存在 `rom/2d/spr_sel_md...cmn.farc` 等图片归档，但本轮没有解码 sprite、核对 UV 或渲染图片，不能称为缩略图已支持。

## 第一步：核心功能实现

### 游戏角色分类（按用户截图修订）

角色下拉固定遵循游戏显示顺序：初音未来、镜音铃、镜音连、巡音流歌、KAITO、MEIKO、衍生角色、随机。额外提供“全部角色”作为搜索聚合入口。不能按样本中出现的 token 动态生成角色菜单，不能将 SAKINE、NERU、HAKU、TETO 或 GUMI 单独提升为游戏一级分类。

保留原始 chara 用于解析与诊断，新增独立的搜索分类映射；NERU／HAKU／SAKINE／TETO 归入衍生角色。Megpoid 的20条 SAKINE 在界面显示“衍生角色”，GUMI 通过名称和 Mod 来源检索。实际跨分类调用用经过验证的 UI 分类映射，不能用元数据枚举序号替代。

“随机”保留为游戏分类入口，但本轮21个静态实体不生成随机伪服装；选中时显示无匹配。原生随机特殊条目的ID、成员规则与定位语义另需验证，不能将随机解释为全部服装或随机装备。

此修订优先于本文其他地方的原始 token 描述：表格中的 SAKINE 等仅是底层证据，最终角色筛选与卡片使用游戏分类名称。

### 1. 自动建立 Mod → 服装索引

- 在 `customization_catalog.cpp` 接入普通 FArc/FArC 指定条目读取，设目录、文件大小、解压长度和文本记录上限；不支持的加密／其他格式显示诊断。运行时离线、后台解析，不调用 Python。
- 复用 DML enabled、priority、include 的目录身份与顺序；当前歌曲 `catalog.cpp` 可参考其发现规则，服装实体独立建模。显示名可重复，SourceId 不能按显示名去重。
- 解析实体表和名称补丁；实体定义、名称来源、其他关联贡献分别记录。追加 mod_gm 表按优先级整条覆盖；普通 gm 表按逻辑路径取生效替换，不能全部累加。保持 id=0 合法。
- 相同 Module ID 只形成一个有效卡片，详情显示胜出定义与命名来源。Mod 过滤按关联来源；区分该 Mod 提供的定义数、当前胜出定义数、关联项数，不把被覆盖版本当另一个可装备版本。
- 保留手工导入清单与基础／DLC导入路径；自动 Mod 索引与导入数据的优先级必须显式规定，避免同一表被重复导入。磁盘快照变化标为需重启／目录过期。
- UI 显示“当前可检索的元数据”，不把 Mod 磁盘记录总数称为当前原生列表可用数。纯纹理替换 Mod 无实体表时给出无法归属的诊断，不虚构实体。

验收：两个真实样本分别解析20和1个定义，X 中文名称映射到997；完整启用 Mod 集合完成覆盖合并后另核对有效数量。补充坏归档、重复ID、孤立名称、禁用Mod、同名Mod、语言与优先级回归。

### 2. 接入已验证的原生定位

依据 [实验报告](research/CUSTOMIZATION_EXPERIMENT_REPORT.md) 与 [交接说明](research/CUSTOMIZATION_NATIVE_INTERFACE_HANDOFF.md)。

- 新增独立 Module 定位适配器，接 `customization.cpp` 的上下文／能力接口与 `mod.cpp` 请求路由，不走歌曲定位器。profile 校验构建、入口指令及对象关联。
- 在 RVA `0x6910B0` 模型帧取得真实页面与上下文；不沿用 manager+0x1A8、堆地址或旧线程号。维护页面／菜单／槽位／范围 generation，请求携带稳定ID、分类、槽位、范围、目录指纹和 serial。
- 帧线程状态机：校验上下文 → 必要时调用 `0x694D00(page,±1)` → 验证分类变化 → 重读 `+0x70/+0x78` 当前列表 → 唯一查找ID → 暂存 `+0x30` → 写目标索引 → 同帧 `0x6916E0(page,1)` → 恢复缓存 → 跨帧确认实际分类、索引和ID。
- 不根据函数返回寄存器宣布成功；确认超时、页面失效、目标缺失、重复ID、目录变化与玩家新操作均应返回中文原因。失败恢复不能覆盖玩家后续操作。
- 初始仅开放已验证 MIKU/RIN 上下文。SAKINE 与其他分类需补主动实测映射，才开放对应跨类定位。Megpoid 可以先完整搜索，定位显示“该原生分类尚未验证”；X ID997 的高ID可见性与定位仍须实机验证。

验收：原实验316↔394、RIN40↔MIKU394在C++ DLL内重复通过；补页面退出／重建、切槽位、列表过滤、请求过期和连续定位测试，保留前后截图和真实ID读回。之后扩展SAKINE及GUMI高ID。自动测试、预览通过与实机通过分开记录。

## 第二步：UI 实现

> 图片与布局最新修订见 [官方与Mod预览方案](MODULE_PREVIEW_PLAN.md)：图片优先、两行文字、悬浮详情、宽图布局，以及官方CPK资源自动读取。此修订替代下文早期常驻右侧详情和手工图片导入的默认方案，最终用户不需导出任何资源。

样式稿：[可交互 HTML](../design/module-search-preview.html)。使用上述21个真实实体的最小元数据，无游戏模型或图片资源；搜索、来源／角色过滤、排序、选择与详情可操作。定位按钮只展示说明。底部键盘提示是最终原生UI规范，HTML样式稿未完整实现该键盘协议。

- 延续现有深色搜索窗口与青绿色选中态，顶部模式、整行搜索框、可换行的角色／Mod／排序工具区。
- 主体为卡片自动换行，列数取决于可用宽度和最小卡宽，只纵向滚动；卡片固定预览区、两行名称、角色、来源和ID。右侧为所选详情；窄窗口改为下方详情，保证至少一列卡片。
- Mod 下拉显示“全部／来源名与计数”，与歌曲曲包过滤一致；提供名称／Mod检索模式，来源详情明确实体定义、名称补丁与覆盖关系。样式稿用目录短名展示来源身份，原生实现使用配置显示名并可附目录区分。
- 接入有来源证据的本地缩略图和异步缓存；未解码或风格缺图使用“暂无预览”。如从 sprite 导出，必须验证数据库、sprite名、纹理与UV；不把游戏裸纹理直接交给DX11后端。
- 原生卡片单击选择，详情按钮／格子焦点Enter提交定位；文本框Enter等待最新查询再提交。与旧“Enter仅详情”行为切换时统一调整输入路由与说明，禁止提交旧结果。成功后是否关闭沿用设置，失败保留筛选和选择。
- Tab进入单一格子焦点，方向键按当前列数移动，支持Home/End/PageUp/PageDown；搜索框左右仍编辑文字。IME组词时暂停搜索／导航；切模式清空待定位动作。
- 明确显示读取中、空库、无匹配、目录过期、不在模型页、未验证分类、目标不在原生列表、定位中与结果；元数据存在不等于已购买或可定位。

验收：共用C++ Preview验证1／2／多列、窗口改宽、长名称、缺图、末行缺角、纯键盘与IME；浏览器布局截图仅为设计参考。最后在游戏中检查真实窗口、输入隔离、定位结果与其他Mod共存。

## 补充样本与即插即用要求

用户后续明确：正式版本必须自动读取当前启用Mod中的服装，不要求手动解包、导出或填写导入清单。此前手工导入只是已有开发基础，可保留为可选兼容路径，不能作为正常使用前置条件。运行时原生FArc/FArC读取和来源合并属于第一步必交付项；当前HTML内嵌数据仅用于设计展示，不是最终运行机制。

两个目录都在此前读取的游戏DML priority中。样式稿已加入XHD的75件，三个有实体表来源共96条静态样本；这不是全游戏合并后的服装总数。

Misaki的PVDB确实包含`performer.*.pv_costume`（例如10013、795、9997）及chara字段，这是PV演出使用的服装资源引用，不能直接当作原生可选择Module ID，也不证明存在可检索的新服装。目录存在objset等演出资源，后续如要覆盖PV专用服装，应与玩家可选Module分开立项。

自动来源检测必须区分“有服装实体定义”“只有歌曲／PV或资源替换”“格式不支持／读取失败”“需运行时核查动态注册”。无标准表的包不能一律报错，也不能虚构0件已被全面证实。歌曲来源与服装来源是独立关系，当前歌曲可关联其他包的服装；读取当前曲目不等于服装归属判定。若未来需要动态DLL服装，需运行时实体集合与磁盘索引对账，未知来源保留明确状态。

先完成自动目录和两个真实样本的解析回归，再集成限定原生定位，随后将此布局落实到现有 ImGui UI、接入资源、做原生预览，最后执行C++ DLL实机验收及分类扩展。核心与UI分为两项工作，本轮按用户最终要求由主任务直接分析，不另开subagent。

本轮只核查两份静态表，未穷举所有启用Mod的定义冲突，也未证实这21项在当前游戏过滤条件下全部可见。没有修改游戏、存档、Mod配置或加载顺序。
