# 受控服装定位验证 04

日期：2026-10-29。结论：**已通过 Frida 探针在实际游戏帧线程主动调用原生列表控件初始化函数，完成同页、同角色分类的服装 ID 394 定位，并恢复 ID 316；标题、中央卡片与高亮画面一致。** 可以开始受支持构建中同页同分类的最小 C++ 适配实现；不能据此启用跨分类、任意菜单或发型／饰品定位。

这不是已部署的搜索 DLL 功能。本轮仅改 artifacts 下探针和独立研究文档，未修改业务源码、装备或存档接口。主动调用已由用户明确要求编写脚本、受控内存修改并验证而授权。

## 当前构建与实验范围

进程 7044，主程序哈希与第三轮一致，基址 0x140000000；控制器 0xE97EF2C0、页面 0xE9723CD0 均从本进程前次原生调用观察获得，并在每个受控阶段检查虚表、控制器关联及上下文。只在实际模型帧入口 RVA 0x6910B0 的返回回调执行写入／调用，线程核对为本进程 9972。线程编号、PID 和堆地址不是可移植 profile，不能硬编码到插件。

固定实验范围：初音未来分类、歌者 1 所在已观察槽位原值 0、当前曲设置、过滤全、244 个有效项目、无操作弹层、无候选试穿。已知对照目标「无上之选(-5)」ID 316 与「向上向上！(0)」ID 394。

## 第一步：单索引写入不足

脚本 controlled-index-pair-v1.js 在模型帧返回时只写页面 +0x110 的 int32：156→155，记录跨帧读回，20 秒后恢复 156。第一次截图的文件时间是 23:05:44，晚于 23:05:23 恢复时刻，故不能用于评价定位期间的 UI；不将其当作失败画面证据。

随后 v2 延长到 60 秒，并将加载脚本与立即截图放同一次编排。23:07:18.557 启动、23:07:24 截图、23:08:18.605 恢复。有效期间截图中底部名称变成「向上向上！(0)」，但中央轮播与卡片未同步到目标，出现选框和卡片不匹配。**排除直接写 +0x110 作为最终定位方案。**

两次均在同上下文下自动恢复，原始状态没有被玩家或其他逻辑改变；试穿两处字段始终 0。脚本的自动恢复受上下文守卫限制，不承诺离页后仍强写旧对象。

## 第二步：取得真实列表与 ID 映射

只读完整正常路径 RVA 0x6916E0 的代码，观察到页面 +0x78 减 +0x70、右移 3 位作为条目数。因此核对这两个指针为当前列表 begin/end，八字节元素为记录指针；不再沿用之前错误猜测的其他向量窗口。

真实样本得到 244 项，记录首 int32 为稳定 ID 的依据来自多个对照：

执行原生实验前遍历全部 244 个记录的首 int32，要求目标 394 唯一、实际位置为 155，并核对当前索引对应 ID 316。代码实例固定目标只是受控实验，实施时必须按请求 ID 在当前生效列表查找，不能使用搜索结果行号、sort_index 或离线表序号。

## 第三步：原生控件调用成功

RVA 0x6916E0 的正常函数体已只读到 ret：RCX 为页面 this，DL 为布尔标志；它先重置页面 +0x110 控件，选择页面 +0x2C 的关联位置，DL 为真且 +0x30 非负时改用 +0x30，构造含可见项数量 11、列表数量及初始位置的描述符，调用通用控件初始化 RVA 0x22BAE0。该路径没有直接进入已发现的 Confirm／Preview／装备或存档入口。原生列表准备函数 0x691390 的内部正常路径会调用它。

受控探针 controlled-native-choice-v1.js 中采用的 Win64 调用形状为 `void(pagePointer, uint8 useRelated)`，返回值不作为成功码。它不是「传 Module ID」接口，需要先以真实列表将 ID 映射到索引。

受控定位步骤：

1. 在实际模型帧线程、同一已验证页面检查分类、槽位原值、列表边界、无弹层／试穿、初始 ID 316 及位置 156。
2. 将已读页面 +0x30 的关联位置缓存暂存，临时写目标索引 155；不改控制器的装备或试穿字段。
3. 同帧调用原生 0x6916E0(page, 1)，让控件按目标位置重新初始化。
4. 无论函数正常返回与否，在 finally 中同帧恢复 +0x30 原缓存 156；不永久伪造推荐关联位置。
5. 按原生列表记录独立读回当前位置及稳定 ID，检查试穿两字段仍 0；截图验证卡片位置与名称。
6. 30 秒后在相同上下文调用同一方法恢复原位置 156，并复核列表 ID 316、缓存 156 及最终截图。

该暂存缓存方法是已实测的开发适配路径，尚不是已证明游戏提供了专门任意 ID 选择 API。后续可进一步找通用控件 setter，减少依赖内部缓存；最小实现应严格限定当前页／当前分类，并保留 profile 与失效守卫。

## 实施可用范围与剩余工作

**现在足够开始的最小实现**：复用现有 UI，在受支持构建、已打开并处于安全状态的 Module 页、当前分类列表内查目标 ID；在模型帧线程复用本轮原生控件初始化方式，随后跨帧确认 ID 与视觉位置。通过失败守卫拒绝过期、跨分类、不在列表或锁定状态未知的请求；不自动试穿／装备。

仍需补齐后才可称完整支持：稳定获得活动页面对象（不能使用旧 manager+0x1A8），请求 generation 和生命周期失效；模型槽位／当前曲与共通范围的独立读取；多目标与不同过滤回归；Mod 高 ID、隐藏／未购买项目；跨分类完整刷新路径；C++ 插件实际集成后的线程、输入和长时间验收。本轮没有全面监测所有内存写者，不能从探针未直接写装备字段推导“所有隐式装备／存档字段绝不变化”。

本轮方法用于高亮、标题与原生卡片轮播定位；三维候选试穿仍是 Enter 菜单的独立动作，已设定大模型保持默认是当前原生交互的正常现象，不能自动确认装备来制造换装预览。
