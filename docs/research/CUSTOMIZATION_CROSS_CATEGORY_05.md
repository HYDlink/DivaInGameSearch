## 原生分类函数与调用形状

本轮只读完整正常路径：入口 RVA 0x694D00 跳到 0x201564A0。代码将 RCX 保存为页面，EDX 保存为分类增量；读取当前分类，存在配置／槽位可用性检查；允许切换时以当前分类和增量计算新 UI 分类，写回分类字段，再调用分类 UI 刷新 0x693830、0x6940F0，以及 0x691390(page,0,1) 重建当前列表，最后播放音效。

本轮主动验证的 Win64 形状为 `void(pagePointer, int32 direction)`，增量 -1 从 RIN→MIKU，+1 从 MIKU→RIN。未把任意目标分类直接写进控制器；保留原生约束检查及刷新链。如果原生拒绝切换，适配器必须检测无进展并退出，不能强写绕过。

该函数会读取配置／保存数据以检查可用性；读取不等于调用存档写入。本轮没有选装备或购买，也没有直接调用 Confirm／Preview／保存入口；未全面跟踪所有写者，因此不宣称对所有模式无任何隐式持久化。

目标列表中的最终定位继续使用已在第 04 轮验证的 RVA 0x6916E0(page,1)：按实际 ID 查出位置，暂存页面 +0x30，临时写目标位置，同帧调用并 finally 恢复原缓存。函数重建原生横向列表控件，而非仅写 +0x110。
