# DIVA Mega Mix+ 原生服装定位完整实验报告

日期：2026-10-29。时区：Asia/Shanghai；本报告中的时刻均为北京时间。状态：研究和受控验证已完成到 MIKU/RIN 范围，未集成或部署生产搜索 DLL。本报告统一取代各轮报告中的旧阶段结论；各轮原始正负证据保留，不覆盖历史。

## 1. 交付结论

**已完成真实游戏中的主动原生服装定位，不再只有变化地址或候选函数。**

1. 同分类：从初音未来「无上之选(-5)」ID316 定位到「向上向上！(0)」ID394，标题、中央卡片和高亮一致，再恢复 ID316。
2. 跨分类：从镜音铃「镜音铃(-1)」ID40，经原生分类函数进入 MIKU，再定位非推荐 ID394，左侧分类、标题和卡片一致；随后经原生函数恢复 RIN 和 ID40。
3. 上述实验均由 Frida 探针在游戏自己的模型帧线程调用原生函数完成，附有真实列表 ID 读回、定位期间截图和恢复后截图。
4. 没有选择更换或购买，没有直接调用装备／存档入口；候选试穿与确认装备保持独立。未全面监测所有写者，因此不能把此结论扩展为所有模式下绝无隐式持久化。

**规划决策：资料足够开始受支持构建、已打开模型页、MIKU/RIN 分类范围的最小 C++ 集成；不足以直接发布全角色、全槽位、任意 Mod 的通用支持。** 实现的核心工作是安全上下文、帧线程请求、真实列表映射、原生分类／控件调用和跨帧验收，不能再把主任务误定为重建搜索 UI。

使用本机 REA 6.7.0 已连接工具、Frida 和指令解码。没有安装或使用可用的 Ghidra／IDA provider，没有将线性反汇编称为完整控制流、反编译或函数签名认证。参考源码为本地 NewClassics、DML、ReDIVA 等，只读使用；未直接移植歌曲地址或 Switch ABI。

## 4. 实验方法与证据分级

- 只读字段：在已知操作前后采集有限窗口和限定字段，不做全进程内存转储。
- 静态线索：Frida 读取本机指令、参考 PC 源码、RTTI／虚表归属；不能单独证明可安全调用。
- 观察插桩：限定三个函数、最多 64 次有效调用、六分钟窗口，记录 this、线程、调用者、原始寄存器和前后字段，不改参数或返回值。
- 受控主动实验：用户明确授权后，仅对已验证对象和目标执行有恢复的单字段写入／原生调用，帧线程和上下文均有守卫。
- 实际画面：保存并打开检查游戏截图，与真实列表 ID 和高亮状态交叉核对；最终图不能代替中间阶段画面。

后续按用户要求采用同一 Frida Session 的批量阶段实验：200 毫秒采样、连续三次一致记录稳定事件、每五秒心跳，并限制事件数量和时限。稳定过滤可能漏掉短瞬态，不能把没有变化消息当作调用从未发生。调用观察与稳定快照分开报告。

## 7. 原生函数与线程结果

所有地址均为相对主模块的 RVA，只对已核查构建成立。

| RVA | 本次确认程度／职责 | 使用条件 |
| --- | --- | --- |
| 0x6910B0 | 模型页面帧入口；本轮受控调用在其返回回调执行 | 获取真实 this，校验页面／控制器及生命周期；不硬编码线程9972 |
| 0x6916E0 | 已主动调用并验证的横向控件初始化函数 | Win64 void(page, uint8 flag) 形状已受控使用，flag=1；先查列表ID |
| 0x694D00 | 上下切 UI 分类的原生函数，主动±1与画面通过 | Win64 void(page,int32 direction)；保留原生可用性判断及刷新 |
| 0x691390 | 原生列表准备，观察五次调用 | 被页面进入、分类切换和推荐返回共用；不等同任意目标接口 |
| 0x6912C0 | 三次1+3实际命中的推荐返回路径 | 先查分类再刷新；不是本轮任意目标定位的最终方案 |
| 0x695520 | 已读短函数，间接读取控制器+0x40 | 分类读取交叉依据，尚未作为生产 getter 部署 |
| 0x695EE0 | Main 状态更新／输入处理线索 | 用于收敛调用链，未主动调用 |
| 0x693830／0x6940F0 | 原生分类函数内部的 UI 刷新 helper | 本轮由原生分类函数调用，未单独认证成通用 API |

第三轮记录：0x6912C0 命中3次，0x691390命中5次，0x694D00命中1次；九次进入／离开均完整，线程均9972。推荐内部嵌套准备函数的返回地址为RVA 0x691321，分类内部调用者为0x20156551。原始 R8D 高位出现残值，只能结合静态 mov r8b,1 使用低字节线索，不能照抄高位垃圾值作参数。返回寄存器0x7/0x9/0xC不是已确认bool或成功码。

0x6916E0 正常函数体已读取到ret：先重置+0x110控件，读取关联位置，在DL为真且+0x30非负时使用该位置，构造包含可见项数、列表数量、初始位置的描述符并调用通用控件初始化0x22BAE0。没有直接进入已识别的更换／购买／保存分支；不把完整程序所有间接副作用都视为已经证明。

0x694D00 跳至0x201564A0：RCX页面、EDX增量；读取配置／槽位可用性，允许时更新分类并刷新UI，再调用0x691390重建列表。读取到保存数据用于判断不等于写存档。静态代码含八槽计算，不能据此认为全部槽位均已测试或与底层角色枚举一一对应。

## 8. 已验证的定位配方

### 同分类

1. 在模型原生帧线程取得实际页面this，核对构建、虚表、控制器、上下文代数、无弹层和试穿。
2. 读取当前列表边界，检查数量、索引及可读性，在当前列表按稳定Module ID唯一查找目标。
3. 暂存页面+0x30，将目标索引写入该参数缓存。
4. 同帧调用0x6916E0(page,1)，finally恢复原缓存；不直接写装备字段。
5. 跨帧从当前列表独立核对选中ID、分类、数量及上下文；再以实际画面验证名称和卡片一致。

这是受控验证过的缓存暂存＋原生控件方法，并非发现了一个官方SelectModuleById函数。后续可寻找更直接的通用控件setter，但不得退回只写+0x110。

### 跨分类

1. 保存起点分类与稳定ID，保持歌者槽位和当前曲／共通范围不变。
2. 调用原生0x694D00切换分类。当前只验证相邻MIKU/RIN的±1，不假设任意步长有效。
3. 核对分类确实变化，重新读取新列表，重新按ID匹配，再按同分类方法定位。
4. 原生拒绝切换、无进展、目标缺失、ID冲突或上下文改变时停止并给出明确结果；不强写分类或装备绕过。
5. 恢复时按原生分类路径回到起点，再按原稳定ID重新匹配，不能复用旧索引。外部玩家已改变选择时不应无条件覆盖。

## 9. 失败方案、误判与修正

1. 菜单5/6/1在选曲及定制主页相同，排除用它单独识别定制子页。
2. 起初通用控制器窗口对高亮移动不变；后来定位到真实模型页面，避免无限扩大扫描。
3. F1最初被误当候选试穿；经用户说明和单独实验更正，混入F1的推荐样本不独立归因。
4. 0x694D00最初称相对移动候选；实际调用证明是分类移动，排除为左右服装选择接口。
5. manager+0x1A8曾在旧进程找到Module Scene，新进程虚表校验失败；禁止移植为稳定对象入口。guard拒绝读取是正确行为，不是游戏页面损坏证据。
6. 只写+0x110跨帧读回成功但轮播不完整，最终方案必须走原生控件初始化。
7. 第一次20秒写入实验的截图晚于恢复，不能用作定位期间结果；第二次将加载与截图放同一编排并延长窗口，取得有效部分失败图。
8. 自动按键API返回成功不等于游戏消费。两次Return、一次Down未改变主页，自动输入未建立有效性；之后玩家一次完成批量操作。没有持续盲发Enter。
9. WGC图形捕获连续超时；NativeCapture隔离环境无法枚举窗口。按项目指南取得交互桌面命令执行权限后，PrintWindow/GDI获取有效画面。
10. 首次hook守卫错误地把push rbx限为单字节0x53，因前缀而拒绝安装；改为按完整指令核对后安装。没有把该守卫错误当作游戏不兼容。

## 12. 给实施规划的具体输入

### P0：最小服装适配

复用现有搜索UI和目录，不重写。先限定受支持构建、已打开模型页、已验证分类；实现profile检查、从模型原生帧取得实际this、请求队列、generation／目录指纹校验、真实列表唯一ID匹配、原生分类及控件调用、跨帧结果确认。

请求至少包含kind、稳定ID、元数据人物与显式UI分类映射、歌者槽位／设置范围上下文、contextGeneration、catalogFingerprint、serial。不能只传一个数字，也不能把UI分类直接static_cast为CustomizationCharacter。

结果至少区分UnsupportedBuild、UnavailableContext、ContextChanged、NotInList、DuplicateId、CategoryUnavailable、PreviewPending、Success。离页、换槽位、目录变化或实例变化使旧请求失效；不在DllMain初始化业务，不在帧回调阻塞，不从工作线程调用这些游戏函数。

生产方案以真实帧回调与profile解析对象，不使用本机堆地址或旧manager+0x1A8。保留其他Mod hook链，新增hook仅服务明确生命周期和执行点。成功来自实际列表ID及UI状态，不把NativeFunction返回值当成功码。

### P1：补充验收后扩大

优先补LEN及其余主要分类、分类映射、其他槽位、共通设置；之后补过滤变化、未购买／隐藏／锁定、高ID、目标不存在与上下文失效恢复。分类函数原生拒绝时不强行写内存绕过；跨分类多步要限制次数、逐次验证进展，不能盲循环。

调试探针自动恢复是实验手段，产品定位成功后不自动跳回。产品只在失败恢复策略明确且上下文未被玩家改变时尝试恢复，不能覆盖玩家的新选择。

### P2：发型和饰品独立研究

可以并行做离线表和参考源码研究，实际游戏实验一次只由一个任务控制。KAMI、ZUJO/FACE/NECK/BACK、ALL、绑定、无装备和隐藏锁定分别采样；不要因为Module已定位就宣布其他领域共用函数或存档布局。

### 可直接交给下个任务的工作说明

以本报告第04/05轮成功证据为基础，先实现受支持构建、已打开Module页中的最小原生定位。必须复用现有UI，解决实际页面获取和generation失效，再在模型帧线程执行分类切换、真实列表ID匹配和原生控件定位。保留装备／购买／存档确认由玩家完成；先做MIKU/RIN和已验证ID的C++实机回归，再扩大角色和数据范围。不得直接照抄实验PID、线程ID、堆地址或只写索引，也不得把Frida实验通过等同于DLL已经通过。
