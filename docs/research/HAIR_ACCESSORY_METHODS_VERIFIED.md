## 缩略图结论

发型KAMI和头、脸、胸口、背部共用cstm_item稳定ID空间。真实资源名称为：

```text
SPR_CMNITM_THMB%03d_ITM_IMG
SPR_CMNITM_THMB%03d_ITM_IMG_FT
```

`%03d`是最小宽度，ID大于999时不能截断。必须查实际SpriteDatabase取得集合文件名及sprite索引，不以ID推算集合编号或hash。集合通常为 `spr_cmnitm_thmbNNN.bin`，资源通常为相应FARC里的同名BIN；最终以数据库结果为准。

已有 `DivaSpriteDatabaseFind/List`、`DivaFarcReadEntry`、`DivaSpriteDecode` 可复用。解码器必须从桥接同目录加载；产品沿用后台队列、LRU和DX11上传，不能每帧读CPK。

本机有效目录：482发型、204道具。实际官方及已启用Mod资源全量解码：**1372个ID／风格组合通过**。75发型没有FT专用条目，另有道具99的FT裁切无效、发型608的FT索引越界；这77个组合使用同ID通用图回退，原始失败保留。其余组合直接解码对应精灵。

这证明当前磁盘配置的图片读取方法，不等于所有Mod配置、同名数据库冲突或所有平台资源已认证。产品仍须严格处理普通数据库替换、追加数据库合并、同优先级歧义和生效FARC来源，不能把候选全集无条件合并。不得修改其他Mod中的两份无效资源来掩盖失败。

## 实际列表布局

以下偏移相对当前活动scene；先通过场景树、虚表、状态机及配置身份核对活动对象，不能全局扫到对象就使用。

| 字段 | 发型 | 自定义道具 |
| --- | --- | --- |
| 活动页键 | 3 | 4 |
| 原生记录指针向量begin/end | +0x108 / +0x110 | +0x48 / +0x50 |
| 高亮控件及当前索引 | +0x138 | +0x78 |
| 控件数量 | +0x144 | +0x84 |
| 状态机指针 | +0x3A0 | +0x300 |
| 动作目标索引／记录 | +0x38 / +0x40 | +0x38 / +0x40 |
| 动作回调对象 | +0x378 | +0x2D8 |
| 回调函数RVA | 0x68AC40 | 0x68F430 |
| 部位 | 固定KAMI | +0x30：头0、脸1、胸口2、背部3 |

向量每项8字节，保存记录指针；记录首个int32为稳定ID。验证 `end-begin=count*8`、数量上限、索引边界、唯一目标及记录可读。列表里的负值随机／特殊项不能变成普通目录实体。

实机四部位分别95／52／25／32项；每个部位的全部ID集合与当前目录逐项比较，差异均为0。当前初音发型列表204项，含特殊随机项；不能把这个数量当作全角色发型总数。

## 原生定位方法

1. 在本页空闲、控件无过渡时，从真实列表按稳定ID唯一查索引。
2. 在匹配的 `0x66B2D0` 原生状态机帧末，调用 `0x22D250(control,index)`，control取上表对应偏移。
3. 更新卡片显示：发型 `0x6891F0(scene,3)`，道具 `0x68D180(scene,3)`。
4. 后续帧重新从真实向量和高亮索引读取稳定ID，并核对画面名称。列表、人物、槽位、曲目、范围或配置变化即取消。

**不能以 `0x688780`／`0x68C750` 作为定位后的刷新**：它们重建列表，实测会把高亮重置为原项。第一轮错误路径已按断言停止；修正后头41↔42、脸0↔1的跨帧读回和截图通过。

道具部位切换入口为 `0x68EF00(scene,direction)`，自然Up/Down已观察到-1/+1、四部位与列表重建；生产应每帧最多走一步，到达后重新取向量。当前研究中的跨部位操作仍使用AHK，不把自然观察冒充该入口主动调用已全部通过。

## 动作方法与恢复

动作回调对象的+8绑定scene，+0x10绑定上表对应RVA；执行前重新核对绑定。自然确认菜单准备的目标字段是scene+0x38索引及+0x40记录。菜单取消会清空目标，不能依赖上一次菜单的残留记录。

受控调用从空闲列表准备经过唯一ID核对的目标字段，再调用回调；目标必须已拥有、属于当前可操作人物与槽位。研究脚本只开放已逐项看图核对的代表样本白名单，**产品禁止照搬该白名单，必须接实时拥有判定**。

| 动作 | 发型回调命令 | 道具回调命令 |
| --- | --- | --- |
| 已拥有目标更换／配置 | 3 | 4 |
| 临时预览 | 7 | 7 |
| 卸除 | **6：搭配模型**；后续专门自然观测与注入复现已确认，见下方说明 | 5 |

2026-11-03专门卸除补验见`HAIR_ACCESSORY_REMOVAL_VERIFIED.md`：发型无需先定位默认发型再更换，当前装备菜单实际调用command6；四道具部位分别实测共用command5。旧的“选择默认发型后普通更换”仍是已有恢复实验，但不是该菜单卸除命令。

不开放购买分支。最关键的布局区别：**scene+0x10为待进入状态，+0x14为加载完成后的返回状态**。回调先准备字段；对状态机调用 `0x66B3A0(manager,sceneNext)`，先进入加载状态3，再由原生加载完成进入预览2或普通列表0。若直接把+0x14的2当作下一状态，会跳过原装备备份，造成旧备份恢复；该错误路径已实测拒绝并恢复，不能投入产品。

原生预览中可用AHK Esc自然退出；正式产品退出应单独认证发型／道具对应返回分支，不能借用模型退出布局。预览中禁止提交没有退出旧预览事务保护的新动作。

当前槽位显示配置位于 `controller+0x320+slot*0xE0`：模型+0、头+4、脸+8、胸口+0xC、背部+0x10、发型+0x14。预览期间这些值会临时变化，**不是独立持久装备证据**。`0x680A30`只是复制此显示配置；不能把它包装成独立存档读回。

预览必须先保存真实原装备并验证退出恢复；装备完成还须验证原生加载结束和其他五个槽位保持。持久配置getter、未拥有目标拒绝、其他人物／槽位、共通范围和保存／重启效果仍需生产接线后补验。
