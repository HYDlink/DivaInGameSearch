# 发型搭配模型与四部位卸除：实机协议及实施交接

日期：2026-11-03，亚洲／上海。本报告专门补齐“卸除”，复用已有页面路由和定位研究。构建 SHA256：`6F4DF714C28515C93B3023E7D6DAFA9095DD8835F762D54DB1726FB8BC04504D`。地址均为主模块 RVA，运行时加实际模块基址。

## 结论与验证范围

**发型“搭配模型”的直接菜单命令为6；头、脸、胸口、背部的“卸除”共用命令5。** 它们是原生动作，不需要直接写装备ID为-1，不涉及购买，也不用选一个名为“无”的目录实体。

| 对象 | 活动页键 | 回调RVA及签名 | 命令 | 实机样本 | 卸除后当前配置字段 |
| --- | --- | --- | --- | --- | --- |
| 发型 | 3 | `void 0x68AC40(scene*, int)` | **6** | 666，Trip The Light Fantastic发型 | 发型ID=-1，恢复当前模型自带发型 |
| 头 | 4 | `void 0x68F430(scene*, int)` | **5** | 42，女仆头饰 | 头ID=-1 |
| 脸 | 4 | 同上 | **5** | 0，无框眼镜（银） | 脸ID=-1 |
| 胸口 | 4 | 同上 | **5** | 57，蝴蝶领带（金） | 胸口ID=-1 |
| 背部 | 4 | 同上 | **5** | 70，天使翅膀 | 背部ID=-1 |

五类均完成：自然按Enter打开当前装备菜单→Enter卸除，重新配置样本，再由Frida在游戏线程提交原生命令复现；字段和截图分别核验。四部位不是只有静态推断，均有独立实机对照。额外执行了只卸除一次的工具模式，头饰42成功卸除。

这是当前初音、歌姬槽位0、单曲范围（运行时scope=3）的代表样本认证；不等于所有角色、所有物品或共通范围全部通过。显示配置也不能单独证明保存后重启的持久结果。本轮自然getter候选`0x1D5E30`未提供可用独立保存记录，不能据其空日志宣称持久读回认证。

## 已确认布局

对象必须从活动自定义控制器、场景树和已知虚表取得，不能全局扫驻留对象。活动树、页键及manager空闲判据沿用`CURRENT_NATIVE_ROUTING_RESEARCH.md`。

| 字段 | 发型scene | 道具scene |
| --- | --- | --- |
| 记录指针向量begin/end | +0x108 / +0x110 | +0x48 / +0x50 |
| 高亮控件起点／当前索引 | +0x138 | +0x78 |
| 控件数量 | +0x144 | +0x84 |
| 当前部位 | 不使用道具布局 | +0x30：头0、脸1、胸口2、背部3 |
| 动作目标索引／record | +0x38 / +0x40 | +0x38 / +0x40 |
| 回调对象指针 | +0x378 | +0x2D8 |
| 内部状态机指针 | +0x3A0 | +0x300 |

向量元素为8字节record指针，record首int32是稳定ID。确认`end-begin=count*8`、数量与索引有界、目标唯一及可读。回调对象+8必须绑定本scene，+0x10必须绑定上表的回调RVA。

当前显示配置：`controller+0x320+slot*0xE0`，模型+0、头+4、脸+8、胸口+0xC、背部+0x10、发型+0x14。卸除只应让对应字段变为-1，其他五项不变；预览期间这些字段会临时改变，禁止把预览当装备提交成功。

## 注入复现的完整协议

1. 进入对应子页，等待原生列表状态0、无场景切页、无控件过渡；退出已有菜单或预览后才能提交。本轮工具直接拒绝非空闲起点。
2. 固定曲目、配置对象、槽位、范围和部位，读取该部位实际装备ID。为-1时返回“无需卸除”，不调用原生函数。
3. 从当前真实列表按实际装备ID唯一查record/index。当前复现工具先用已认证的控件接口定位该装备，再确认列表身份；不依赖之前菜单残留的目标。
4. 一次性Hook真实`0x66B2D0(stateManager)`，匹配本页stateManager，在onLeave重新检查全部来源与目标。不要在Frida RPC线程直接调用游戏逻辑。
5. 准备`scene+0x38=index`、`scene+0x40=record`。这是自然菜单动作目标，不是装备ID写入。调用发型`callback(scene,6)`或道具`callback(scene,5)`。
6. 本轮自然与注入观测均为：`scene+0x18=4`（本路径卸除操作标志）、`scene+0x10=3`（待进入加载）、`scene+0x14=0`（加载后的返回状态）。不能直接切0或套用其他页布局。
7. 调用已认证状态切换`uint8 0x66B3A0(stateManager,3)`，等待原生加载完成回列表0。返回值1只是受理，不是卸除完成。
8. 连续三次确认稳定列表、对应配置字段=-1且其他五项不变，截图后再次读回。超时停止，不继续盲发Enter，也不直接重写装备恢复。

**发型有独有行为：** 模型316“无上之选”的自带发型在本轮列表中是665。卸除自定义发型666后，原生会将高亮移至665，配置发型字段仍为-1。发型scene+0x30在本例为154，即该默认发型的列表位置；它不是道具部位枚举。本轮静态已有command6分支读取+0x30并准备目标索引，且自然及注入行为一致。不能要求卸除后高亮仍停666，不能把665写入配置冒充移除覆盖。

四道具部位则共享回调与命令，由当前scene+0x30区分部位；因此一个统一道具卸除执行器即可，但必须先切到目标部位并重新获取该部位列表。发型必须使用单独命令6，不能照搬道具命令5。

## 可复用工具

本节提到的研究脚本未随仓库公开，这里只记录当时的做法。

- `scripts/research/item_methods_probe.js`新增`armremove`：经过来源／装备／record／回调绑定守卫，游戏线程帧末单次提交。无直接装备写入。`removalstate`只轮询已确认字段，避免重复读完整目录与无关指针邻域。
- `scripts/research/run_removal_experiment.py`：`--mode compare`自然与注入对照并恢复**进入本轮时**的配置；`--mode remove`只卸除当前真实装备，保留卸除结果。每个部位单独运行，同轮一个Frida Session；退出会卸载并分离。
- `--part`支持`hair/head/face/chest/back`。发型要求发型列表起点；道具允许从发型F3进入，再逐次验证Down切到指定部位。未实现任意游戏页面起点导航，这部分复用既有路由调度器。
- compare只开放已核对拥有的样本666／42／0／57／70；不是生产拥有判定。remove按当前实际装备ID查真实列表，只有当前装备能被移除。
- 单步超时、来源改变或装备变化立即停止。本工具总预算180秒；其他既有实验默认90秒不变。失败不进行隐式装备恢复，结果保留失败现场。

输出目录包含`events.jsonl`、`result.json`及按阶段命名的PNG。日志含时间、配置断言、自然调用参数、脚本哈希及会话分离状态。早期hair/head成功批次的result阶段数组为空，阶段细节在events.jsonl；后续工具已补齐结构化阶段数组，不篡改历史记录。

以下示例适用于Git Bash，在仓库根目录运行；`DIVA_PID`和`AHK_EXE`指向本次进程及现有AHK。PowerShell应使用其续行语法。**remove成功后保留卸除结果**：

```bash
python scripts/research/run_removal_experiment.py \
  --pid "$DIVA_PID" \
  --output artifacts/removal-research/新的发型卸除 \
  --ahk "$AHK_EXE" \
  --part hair \
  --mode remove

python scripts/research/run_removal_experiment.py \
  --pid "$DIVA_PID" \
  --output artifacts/removal-research/新的背部对照 \
  --ahk "$AHK_EXE" \
  --part back \
  --mode compare
```

## 产品实施方案

建议新增`RemoveCustomization(kind, part, expectedEquippedId, contextGeneration)`事务动作；发型UI标签为“搭配模型”，道具标签为“卸除”。仅当搜索结果ID与当前真实装备一致时显示该结果的移除动作；全局“恢复模型发型”则直接读取当前覆盖ID，为-1时无需操作。

沿用既有路由调度器进入发型或道具部位，重新取当前配置／真实列表，定位当前装备，再按上述命令提交。第一版沿用本轮已验证的定位后执行协议；不在本轮没有验证的任意高亮状态下直接跳过目标准备。

执行器应绑定人物、槽位、曲目、范围与generation；每帧最多提交一次，回调重绑定或来源变更取消。UI在原生完成前显示处理中，完成由跨帧读回驱动。装备已为空返回无操作成功；结果不是当前装备则拒绝，避免卸除另一个物品。当前产品C++实现未在本轮接线，不混入其他未提交业务改动。

本报告已足以实现当前范围的原生卸除功能。仍需在产品接线后补验：共通范围、其他人物／槽位、预览中发起移除的取消流程、过滤器导致已装备目标不在列表，以及正常保存后重启。不得把这些边界写成已通过。
