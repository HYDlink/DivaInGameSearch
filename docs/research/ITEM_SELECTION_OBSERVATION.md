# 饰品选择只读对照与静态候选

日期：2026-10-31。目标是利用现有跨页工具缩小饰品定位接口范围，不把变化地址当成已完成原生定位。前提是外层与子页导航已通过实机验证，详见 `OUTER_NATIVE_ROUTING_VERIFIED.md`。

## 两轮批量结果

原始证据：忽略目录 `artifacts/native-routing-research/20261031/item-fields-readonly-01/02/`。每轮同一Session，从稳定选曲经已验证原生导航进入饰品；只在饰品页用AutoHotkey方向键操作，读当前已校验场景前0x120字节和已知状态机。不调用未验证饰品函数，不按Enter，不预览、不装备、不购买。末尾经已验证原生请求退父页、回选曲，均已分离。

第二轮12阶段全部通过。基线、右移、部位下移及左移截图已打开核对：护士帽→女仆头饰；头→脸后为无框眼镜（银）；返回头并左移环绕为爱心（头）。第一轮中的“左移恢复”只是当时阶段命名，实际未恢复首项：部位切换重置了索引，左移从0环绕到94。第二轮明确增加右移，独立断言回到部位0、索引0、数量95，才退出。不能把第一轮误记成完整恢复。

饰品页面初到时可能缩略图为空；额外稳定采样后图标正常，故以后必须区分页面就绪、列表身份就绪及素材就绪。不能只延长固定等待就宣称解决所有异步加载问题。

| `+0x78` | 右移0→1，切部位重置到0，头部左移环绕0→94、再右移→0；确认本轮高亮位置行为，不是饰品稳定ID |

尚未取得稳定饰品ID到当前列表记录的可靠映射，不能直接写+0x78冒充定位完成。

## 静态缩小的入口

通过真实场景虚表取得 `0x68C180/0x68C500/0x68C570` 等入口。`0x68C180`初始化实际绑定：`scene+0x2D8`回调对象，+8绑定scene，+0x10指向`0x68F430`；运行时第二轮额外读回该绑定。内部状态0虚表为RVA`0xCC49E0`，其中真实候选更新入口`0x68FEF0`和输入入口`0x68FF10`。

`0x68FF10`静态分支给出以下有限候选：

| RVA | 静态含义／接续 |
| --- | --- |
| `0x68C700(scene,direction)` | 自然左右分支调用，方向-1／1；尚未主动调用 |
| `0x68EF00(scene,direction)` | 自然部位上下分支调用，方向-1／1；尚未主动调用 |
| `0x68C780(scene)` | 自然确认分支，候选菜单入口；未调用，避免误装备或购买 |
| `0x68C7D0(scene)` | 另一输入分支，功能尚未认证，不当作候选预览接口直接调用 |
| `0x68DB10(scene)` | 状态0更新中的辅助调用，下一步结合列表／控件静态分析 |
| `0x68E7C0(scene,flag)` | 状态更新中的控件辅助候选，含1／2标志，未认证为定位入口 |
| `0x68F430(scene,command)` | 初始化绑定的动作回调候选，命令及签名语义尚未自然观测 |

上述只按已有指令分支命名，并未hook自然调用确认，更未进行候选主动调用。饰品的`0x68C700`与模型的`0x694D00`不是可直接互换的接口；布局及方向语义必须分别认证。

Ghidra输出 `item-scene-static-17.log`、`item-actions-static-18.log`、`item-input-static-19.log`。其中若干虚拟化跳转桩产生跨区域混合反编译、不可恢复跳表或只有LOCK／UNLOCK的伪结果；**这些不作为调用协议证据**。本轮可靠增量来自真实虚表、有限字段对照以及可读的`0x68FF10`输入分支，没有扩张成全局动态Hook。

## 接续与复用

下一轮只针对上述候选做有限自然观测，先验证左右／部位参数、真实记录容器及稳定ID；再单独测试原生定位。自然菜单只读确认后才研究预览／更换命令，不照搬服装command3／7。继续保留来源、部位、当前高亮和原装备的独立读回。

工具 `scripts/research/run_item_observation.py` 默认只接受头部首项基线，以保证已验证恢复序列有定义；初始不符即停止。先从仓库根目录设置当前`DIVA_PID`及现有`AHK_EXE`。分行示例适用于Git Bash，PowerShell需换用其续行符：

```bash
python scripts/research/run_item_observation.py \
  --pid "$DIVA_PID" \
  --output artifacts/native-routing-research/下一轮-饰品只读 \
  --ahk "$AHK_EXE"
```
