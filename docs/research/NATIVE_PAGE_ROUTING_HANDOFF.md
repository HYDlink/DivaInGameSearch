# 页面感知搜索与跨页面定位：晚间 Frida 实验清单

日期：2026-10-30。目标是补充页面识别和原生导航协议，复用已有服装目录、图片和列表定位，不重新扫描服装数据库。本文件是研究任务；不得把待验证地址或假设写成已证实能力。

## 用户要求的最终行为

| 当前页面 | Ctrl+F 默认搜索 | 点击定位后的行为 |
| --- | --- | --- |
| 歌曲列表 | 歌曲 | 在当前列表高亮歌曲和指定难度 |
| 换装父菜单，尚未进入模型或饰品 | 服装 | 进入当前角色槽位对应的模型列表，再高亮目标服装 |
| 模型／服装列表 | 服装 | 保持当前槽位与设置范围，必要时切角色分类，再高亮目标 |
| 饰品列表或对应子菜单 | 饰品 | 后续进入正确部位列表并高亮；当前饰品定位未实现 |
| 其他允许离开的菜单 | 默认领域按明确页面规则决定，仍可手动切换 | 后续支持转到歌曲列表再定位；演奏、载入、保存确认等阻塞状态不能直接套用菜单退出协议 |

只在每次打开搜索时选择默认领域，不在用户操作搜索期间强制切回。手动切换领域保留独立查询。用户希望后续在父菜单点击服装结果即可进入模型列表并定位，Enter／定位按钮应走同一条导航请求；1.0.6卡片已支持单击定位，但父菜单跨页激活仍未实现。定位只改变浏览高亮，不自动装备、购买、确认保存或开始演奏。

## 今晚优先做的三个实验

### 实验一：区分页面、槽位与设置范围（必需）

依次停留：歌曲列表 → 曲目单独设置／换装父菜单 → 模型列表 → 返回父菜单 → 饰品菜单 → 某一部位列表 → 返回歌曲列表。再对不同歌者槽位和共通设置各复走一次，至少两轮进出以排除偶然堆地址。

每一步记录：画面名称、全局current/next/changing、原生任务／子页枚举、活动对象指针和虚表、page/控制器/配置对象身份、歌者槽位、单曲／共通范围、角色分类、弹层／过渡状态。比较模型帧在非模型页面是否仍回调，旧对象是否仍驻留，避免仅凭非空指针／旧快照识别页面。

交付：页面判定表、可靠读取链（模块RVA+字段偏移）、字段类型与有效值、对象创建销毁／重建时机、与截图对应的快照。无法命名的字段保留原始名称，不猜语义。

### 实验二：从换装父菜单进入模型并定位（核心）

只观察玩家手动选择“模型／服装”后触发的原生事件／处理函数、调用线程、this、参数、前置状态和返回过程；不要广泛hook所有函数。确认模型页何时创建、哪一帧可读取完整列表、是否需要单独激活焦点或关闭父弹层。

拿到入口后，在相同游戏帧协议中完成一次：父菜单 → 调用原生进入模型 → 等待真实模型页就绪 → 用现有定位器高亮ID394。再做不同角色目标与第二槽位。保存前后画面、实际ID／分类／索引，并确认没有装备、购买或保存动作。调用返回值只作记录，不作为成功凭据。

同时观察自然返回入口及取消方式：切换中按Esc、用户换槽位、请求过期、目标缺失时如何停止。失败不能跨新配置对象恢复，也不能把玩家送去不相关页面。

交付：进入／返回函数RVA、签名与参数、线程、就绪判据、超时／取消判据、槽位／范围传递方式、一次受控成功和一次取消证据。此实验完成后才能实现“父菜单点服装自动进入并定位”。

### 实验三：验收现有DLL全角色定位（复用，不重逆向）

检查模型页Ctrl+F是否默认服装、读到当前角色；依次检查六位主角色及衍生分类，每类至少一个当前真实列表中的目标。核对名称、卡片、分类、实际列表ID；同类、跨类、连续改查询、关窗取消各测一次。用户截图中左右键修复也在此复测。

保存search-diagnostics.log与操作前后截图，明确是哪个DLL版本。未购买／缺失目标应明确失败，不绕过原生可见列表。此步骤不需要重新搜地址。

## 后续扩展，和今晚核心分开

### 饰品定位

记录父菜单进入饰品、进入各部位列表的原生入口；列表记录结构、稳定ID／部位映射、真实高亮入口；区分高亮与装备。服装控件签名不能直接套在饰品对象上。获得上述协议后再接入饰品定位。

### 从其他菜单转到歌曲再定位

先限定来源：换装父菜单、模型页、饰品页。逐层观察自然“返回到歌曲列表”的退出栈／任务事件、参数、对象销毁和选曲页就绪条件。不能只写全局next菜单字段或强行复用旧选曲对象。

受控验证：来源页 → 按原生协议退出各层 → 等真实选曲对象和列表稳定 → 复用现有歌曲定位器 → 跨帧读回PVID／风格／难度。记录取消、弹层阻塞、未保存更改确认、目标不可用时的行为。退出前不得擅自确认丢弃更改。

“任何地方”需逐类界定：主菜单、选曲、PV观看、商店、演奏、暂停、载入／保存、确认对话框等。先确认允许立即退出的页面；演奏与保存等状态单独定义行为，不承诺同一条退出协议全覆盖。
