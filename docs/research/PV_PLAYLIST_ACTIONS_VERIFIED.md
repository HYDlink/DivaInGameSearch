# 播放列表自定义：预览与更换的实机协议

2026-11-06，亚洲／上海。在已核验的 PC 构建 `6F4DF714C28515C93B3023E7D6DAFA9095DD8835F762D54DB1726FB8BC04504D` 上，对播放列表歌曲 **Hello, Worker**（来源 PVID 730，歌者槽位 0）的自定义页做了受控原生动作实验。所有结论都来自同一 Frida 会话内的只读采样与帧末单次原生调用，动作只做可恢复的预览与更换，最终恢复进入本轮时的配置。

## 结论：三类配置必须分开看

| 对象 | 预览（命令 7） | 更换（命令 3） |
| --- | --- | --- |
| `controller+0x320+slot*0xE0` 临时显示配置 | 变为目标模型 | 变为目标模型 |
| `controller+0x10` 指向的槽位独立记录（步长 `0x1C`） | **保持原值** | **同时变为目标模型** |
| `controller+0x80` 当前装备读数 | 保持原值 | 变为目标模型 |

即：**播放列表的“更换”确实写入了 `controller+0x10` 的槽位记录**，而“预览”只改临时显示。这与普通单曲的独立配置读取路径一致，但播放列表的独立记录只在 `controller+0x10` 出现，不能退回单曲 getter 冒充本槽配置。

实测序列（模型 ID 40 → 恢复 334）：

| 阶段 | 独立记录 `+0x10[0]` | 显示配置 `+0x320` | 内部状态 `state+0x18` | 说明 |
| --- | --- | --- | --- | --- |
| 基线 | 334 | 334 | 0 | 空闲模型列表，分类 1 |
| 原生预览 40 | 334 | 40 | 2 | 命令 7 回调返回 `+0x14=3`、`+0x18=2` |
| 退出预览 | 334 | 334 | 0 | `+0x28` 直连标记为 0，按 `+0x1C=2`、`+0x18=0` 请求状态 3 |
| 原生更换 40 | **40** | 40 | 0 | 命令 3，`+0x14=3`，`+0x18=0`，`scene+0x2C` 记为列表序号 |
| 恢复 334 | 334 | 334 | 0 | 分类 3 中的序号 20，同样走命令 3 |

`scene+0x2C`（列表中的已装备序号）在更换后等于目标在**当前分类列表**中的序号，例：334 在分类 3 的序号为 20，更换后该字段为 20。控制器 `+0x38` 槽位数为 1，`+0x3C` 槽位为 0，`+0x40` 分类随列表变化，范围字段 `base+0x12B5A74` 为 3。

## 已核对的页面与对象

- 外层菜单 `6/7/1`（mode 2、current 6、next 7）与既有播放列表自定义识别一致；模型页场景键 2，场景虚表、管理器、树节点与空闲判据均沿用既有代码。
- 播放列表模型页的分类列表可读：分类 1 有 98 项（首项为模型 40），分类 3 有 91 项（含 334）。分类入口 `0x694D00(scene, ±1)` 每帧一步，实测从 1 依次走到 0、7、6、5、4、3 并有回绕；切换后必须重新读取列表容器与当前分类。
- 拥有判定沿用 `0x1D6510` → `0x1D5C90(id)` → `0x1DA550(record)`；一次状态帧内对当前列表 98 项全部查询，模型 40 与 334 均为已拥有，未发现购买或解锁副作用。

## 与产品动作的关系

产品模型动作协议与本次受控调用逐项相同：读 `scene+0x308` 回调对象、核对 `+8==scene` 与 `+0x10==base+0x695250`、暂存 `scene+0x60/+0x68`、调用 `callback(scene,7|3)`、读取 `scene+0x14` 得到下一状态、再调用 `0x66B3A0(state,next)`。因此本次实验同时验证了产品在播放列表上下文中会走通的三个环节：预览进入、预览退出、更换与恢复。

产品据此做了三处调整（版本仍为既有版本，未升版）：

1. 路由网关不再对播放列表来源拒绝装备／预览／卸除，能力读取也不再强制关闭；跨页导航与歌曲跨页守卫保持原样。
2. 模型动作与发型／道具执行器新增“播放列表外层子状态绑定”：播放列表来源的事务必须保持同一 mode／子状态／配置对象，离开列表即取消；单曲来源沿用既有判据。
3. `ReadEquippedModule` 与 `SavedPcSlot` 在播放列表来源缺少 `controller+0x10` 时返回不可读，不再退回普通单曲 getter，避免把另一对象的配置当成本槽装备。

隔离回归：`原生服装动作守卫验收` 增加播放列表独立记录读取、预览不算装备、预览退出按原记录恢复、离开子状态取消；`原生跨页事务验收` 增加播放列表来源的模型与发型能力开闸及网关受理；`发型道具执行器守卫验收` 增加播放列表事务的外层子状态绑定。

## 仍未实机验收的部分

- **发型与自定义道具**在播放列表中的预览、更换、卸除：场景与命令已由单曲路径认证，但本轮没有在播放列表内逐一实测；产品会按跨帧读回判定，失败时如实报告，不会把临时显示当装备。
- 离开播放列表自定义或保存后重启的持久性；本轮只在同一页面内读回，不能据此宣称已写入存档。
- 其他歌曲、其他槽位、共通范围、跨人物分类的更换；本轮只测 Hello, Worker 的槽位 0 与同一分类内的更换，恢复时另用分类入口跳到 334 所属分类。
- 新 DLL 的实机端到端（搜索面板点击预览／更换）；本轮部署前只有受控原生调用证据。

## 复现

本节提到的研究脚本未随仓库公开，这里只记录当时的做法。

在仓库根目录执行；进程号必须重新查询，输出目录必须尚不存在，且当前游戏应停在播放列表自定义的模型列表空闲状态。脚本先预览、退出预览、更换到当前列表首个其他已拥有模型，再恢复进入时的模型；失败时只尝试恢复独立记录，不写配置字段。

```bash
  --pid "$DIVA_PID" \
  --output artifacts/pv-playlist-actions/新的受控目录 \
  --ahk "$AHK_EXE"
```
