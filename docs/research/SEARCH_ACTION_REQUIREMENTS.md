# 跨页面搜索、定位、预览与换装需求

更新：2026-10-31。根据用户直接指示登记，作为后续研究及实施范围；本文件不是功能已完成声明。

## 用户要求

统一搜索支持歌曲、服装、饰品等模式。用户无需先进入对应原生列表：提交结果后，插件负责识别当前页面、退出必要层级、进入目标页面、等待列表就绪，再执行定位。

服装搜索结果增加悬浮操作：鼠标悬浮任一结果卡片，出现“换装”和“预览”。**2026-10-31用户最新要求：只有鼠标双击搜索结果item才允许触发跨页。** 单击主体在目标原生页可继续原位定位，其他页面只改变搜索选择；Enter及悬浮按钮不能隐式跨页。三种动作必须明确分流，不让同一次点击既定位又换装。目标始终是该结果的稳定实体 ID，不依赖另一张卡片的键盘选中或原生列表旧高亮。实施和界面规则见 [实现计划](../CUSTOMIZATION_ACTION_IMPLEMENTATION_PLAN.md) 与 [交互规格](../../design/CUSTOMIZATION_ACTIONS_SPEC.md)。

用户希望进一步支持不必先改变列表高亮即可预览或换装目标。研究须区别：直接按 ID 操作、内部先完成安全导航与定位再操作、只支持当前原生高亮，不能把后两者宣传成前者。优先打通可验证行为，再确认能否去掉中间列表定位。

## 已知自然路径与待验证项

- 主页可分别进入歌曲选择及自定义；选曲按 R 进入自定义。
- 自定义包含模型、发型、自定义道具等子页。
- 用户提供 F3 在模型→发型→道具→模型间循环，Esc 返回。既有手柄 L3 记录为同层切换线索；需以本机 F3 实测为准。
- 已购买服装正常菜单含更换与预览；未购买服装含购买、购买并选中、预览。必须先识别实际菜单，预览不能落到购买。
- F1 查看当前装备模型，不等于预览搜索目标；候选预览应核对临时模型 ID 和退出恢复。

## 实验与交付要求

统一用 AutoHotkey 执行自然操作，用同一 Frida Session 批量记录时间、页面键、目标 ID、分类、列表索引、弹层、临时预览与装备相关字段，结合原生截图核对。

原生脚本复现必须实际跨页／预览／更换并读回结果，不能只记录函数返回。调用前必须确认上下文、签名、线程与状态；不购买、不绕过未购买限制，不调用未认证保存入口。更换验证需记录原装备并验证恢复；自然游戏流程可能触发自动保存，不能称完全无存档影响。

最终实现应有明确导航及动作状态机、过期请求取消、配置范围与歌者槽位身份保护，产品不依赖 AutoHotkey 或开发机路径。
